# 아이템·스탯 구조 추론안

아래의 구조와 처리 방식은 에이전트의 제안입니다. 접두어 개수와 배타적 확률 분포는 이후 사용자 확인을 받아 확정 규칙으로 이동했습니다.
확정 규칙과 확률의 원본은 [SPEC-0001](classification-and-prefixes.md)에 있습니다.
특정 엔진, 코드 구조, 장비 슬롯이나 조작 방식을 전제하지 않습니다.

## 기본 정의와 획득 개체 분리

같은 종류의 아이템도 접두어와 결과 스탯이 달라질 수 있으므로, 공통 정의와 개체별 상태를 구분하는 안을 제안합니다.

| 개념 | 담을 정보 | 추론 근거 |
| --- | --- | --- |
| 아이템 기본 정의 | 내부 식별자, 이름, 일반·특별 분류, 도감 번호, 기본 스탯 목록 | 공통 정보와 개체별 변형을 구별할 필요 |
| 획득한 아이템 개체 | 개체 식별자, 기본 정의 참조, 획득 경로, 접두어 판정 결과, 적용된 보정 | 같은 아이템의 서로 다른 드롭 결과 보존 |
| 접두어 정의 | 내부 식별자, 표시 이름, 긍정·부정 구분, 대상 스탯과 보정 규칙 | 접두어 이름과 실제 효과 연결 |
| 스탯 정의 | 내부 식별자, 의미, 단위, 숫자 형식, 유불리 방향, 허용 범위 | 부호와 보정 의미를 일관되게 해석 |
| 도감 기록 | 특별한 아이템의 기본 정의 참조, 수집 상태 | 개체가 사라져도 수집 정보를 관리할 수 있는 구조 |

이 표는 논리적 역할의 구분이며 데이터베이스나 엔진 클래스 설계가 아닙니다.
정수·소수 사용 여부, 저장 방식, 개체별 중첩 보관 여부도 아직 정하지 않습니다.

일반 아이템도 내부 식별자는 필요하지만, 이는 플레이어에게 보이는 도감 번호와 별개로 둡니다.
일반 아이템의 도감 번호는 '없음'으로 표현하고 번호 0을 부여하지 않는 안을 제안합니다.
특별한 아이템의 번호는 기본 정의에 귀속시키고, 같은 종류의 여러 획득 개체는 같은 번호를 공유하는 안을 제안합니다.
서로 다른 특별한 아이템 정의 사이의 번호 고유성은 사용자 확인이 필요합니다.

## 접두어 판정 흐름

접두어 개수와 배타적 확률 분포는 [SPEC-0001](classification-and-prefixes.md)의 확정 규칙을 따릅니다.
두 독립 판정으로 긍정·부정을 동시에 부여하는 방식은 확정 규칙에 맞지 않습니다.
아래 처리 순서와 결과 보존 방식은 해당 규칙을 만족시키기 위한 제안입니다.

1. 아이템의 기본 정의와 이번 획득 경로를 확인합니다.
2. 상점 구매라면 접두어 없음으로 처리합니다.
3. 드롭이라면 확정된 배타적 확률 분포에 따라 접두어 구분을 결정합니다.
4. 접두어가 필요하면 해당 구분에서 적용 가능한 접두어를 선택합니다. 후보별 가중치는 미정입니다.
5. 아이템에 이미 있는 대상 스탯에 보정을 적용하고, 판정 결과와 적용된 보정을 개체에 보존합니다.
6. 표시·저장·재접속 때 결과를 다시 추첨하지 않는 안을 제안합니다.

이 흐름은 최초 생성되는 드롭·상점 구매 아이템에 대한 안입니다. 재드롭·되팔기는 별도 규칙이 필요합니다.
상점과 드롭 외 획득 경로를 자동으로 어느 한쪽에 포함하지 않습니다.
후보 접두어가 없는 아이템이나 스탯이 없는 아이템의 처리도 미정입니다.

## 음수를 보존하는 스탯 모델

아이템 스탯에는 부호 있는 수치를 사용하고, 결과가 음수라는 이유만으로 0으로 올리지 않는 안이 필요합니다.
기본 수치와 접두어 보정을 구분해 결과의 근거를 확인할 수 있게 합니다.
특정 스탯 종류와 실제 밸런스 값은 아직 유추할 근거가 없습니다.

보정식 후보로 `결과 = 기본값 + 보정량`을 제안합니다. 이 방식은 0을 지나 음수가 될 수 있습니다.
이는 확정 공식이 아니며 스탯별로 고정값·비율·혼합 보정을 사용할지는 열어 둡니다.

검토용 산술 예시이며 실제 게임 수치가 아닙니다.

| 기본값 | 보정량 | 결과 | 확인할 점 |
| --- | --- | --- | --- |
| 2 | -5 | -3 | 부정 보정으로 0을 통과할 수 있음 |
| -2 | 3 | 1 | 양의 보정으로 음수에서 양수가 될 수 있음 |
| 0 | -1 | -1 | 0도 변화를 받을 수 있음 |

양의 배율만 곱하면 양수의 부호를 음수로 바꿀 수 없고, 음수에 1보다 큰 배율을 곱하면 수치가 더 낮아집니다.
따라서 '긍정 접두어 = 무조건 배율 증가'로 구현을 고정하면 의도와 충돌할 수 있습니다.
재사용 대기시간처럼 작을수록 유리한 스탯이 나중에 도입된다면, 수치 증가와 성능 향상을 별도로 정의해야 합니다.
재사용 대기시간 자체가 존재한다는 뜻은 아닙니다.

아이템의 음수 보정과 캐릭터 최종 능력치의 허용 범위는 분리해 검토합니다.
여러 아이템의 합산, 효과 적용 조건, 최종값 제한 및 계산 순서는 아직 정하지 않습니다.

## 도감 연결 제안

도감의 기본 항목은 특별한 아이템의 기본 정의로 두고, 접두어가 달라도 같은 항목에 연결하는 안을 제안합니다.
접두어별 수집까지 요구하면 별도 변형 기록을 추가할 수 있지만, 현재는 요구되지 않았습니다.
도감 등록 시점이 발견·획득·감정 중 무엇인지, 일반 아이템도 기록하는지, 수집 정보가 계정·캐릭터 중 어디에 속하는지는 미정입니다.

## 조작과 액션에 대한 추론 한계

이번 입력으로 필요한 것은 획득 경로 구분, 접두어 판정, 스탯 결과 보존까지입니다.
줍기 입력, 자동 획득, 장착·사용 방식, 공격·회피·타격 판정은 유추할 근거가 아직 없습니다.
스탯이 조작감을 바꾸는 구체적인 효과를 전달받으면 행동 조건·타이밍·결과와 연결해 확장합니다.

## 검토할 동작 사례

- 상점 구매 개체에는 접두어가 없어야 합니다.
- 접두어로 바뀐 개체가 같은 종류의 다른 개체나 기본 정의의 수치를 변경해서는 안 됩니다.
- 음수 결과는 그대로 보존하고 표시할 수 있어야 합니다.
- 확정된 배타성 규칙에 따라 긍정과 부정이 같은 판정에서 동시에 붙지 않아야 합니다.
- 도감 기본 항목 공유안을 채택하면 접두어 차이로 새로운 번호가 생성되지 않아야 합니다.

도감 항목 공유와 개체 분리·결과 보존 방식은 제안의 검토 기준입니다. 사용자 승인으로 간주하지 않습니다.
